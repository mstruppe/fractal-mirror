Apply the **Mathematical Representation Convention** to: **$ARGUMENTS**

**What this command means (the behaviour sandbox, C-132):** a convention is summoned into a *scope* — the document, section, or task named above (or, with no argument, the work currently in hand). Within that scope the convention's rules are binding; they compose with the Conversation Settings and never override them; the binding releases when the task ends.

**The rule-set (normative source: `Claude/Project Governance/Governance Documents/Fractal_Mathematical_Representation_Convention_v0.1.md` — read it if this summary and the document could disagree; the document wins):**

1. **Define every symbol** — state what each variable and constant means *before* it appears in any equation.
2. **Specify data types** — scalar, vector, or matrix (or a richer type, named plainly), stated per quantity.
3. **Show explicit operations** — multiplication signs written out, never implied by juxtaposition.
4. **State dimensions and ranges** — size limits and expected number ranges for every input and output.
5. **Derive before coding** — the math written out fully in text before any translation into runnable code.

**Procedure:**
1. Bind the scope: restate in one line what the convention now governs.
2. Do the work under the five rules — or, if the scope is an *existing* document, walk it rule by rule and fix (or report, if the document is not yours to edit) every violation.
3. Mark the binding: the produced document carries one line in its banner or sources — *written under the MRC (Fractal_Mathematical_Representation_Convention_v0.1)* — so later readers know the rules it was built to.
4. Release: state that the scope is closed; standing conduct is untouched.

On a client without a slash menu, the plain words "apply the MRC" invoke this same procedure — the ritual is the convention's; the trigger is per-client.
