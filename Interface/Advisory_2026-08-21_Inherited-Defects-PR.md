## 2 · Finding 1 — the opener's "newest handover record" selector (F2 class)

`.claude/commands/pr.md` step 3 reads: *"Read the newest handover record in `Claude/Context Packages/Conversations/`, if any exists."* This selector is nondeterministic: same-date records sort lexically against chronology, and a fresh clone erases file dates entirely. It was written at birth by the kernel's `genesis.py` — not by PR — and is **latent today** (PR has zero handover records); it fires the first time two records share a date, or the first time PR's repo is re-cloned.

**How the defect actually bit, twice:** KNet's Codex session loaded session twenty-five believing it newest while Git showed twenty-six (their diagnostic, Finding B); and on 2026-08-21 the mother's own `Conversations/` held three same-date packages whose lexical order put a one-session-stale package last.

**Cure precedent (two jurisdictions):** an **Active handover pointer** carried in the Local Context's opening line — the exact path is the selector; each close re-points it; frozen records are never renamed. KNet installed it as `KNet_Local_Context` v3.9 (their session twenty-seven, their own P-authority); the mother installed its own the same day this advisory was issued, and cured `genesis.py` so beta-0.8 newborns are born with the pointer convention. **PR's natural moment is its first close:** record the first handover's exact path as the pointer and re-word opener step 3 to read it. Or not — PR's call.
