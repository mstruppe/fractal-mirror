## 2. C-086 — concept foundations (the vision tier of canonical documents)

**The class, in four rules:**

1. **One maturing vision area = one living concept document**, under `/Claude/Architecture/Concepts/<Area>/`, stable filename, version inside (C-012 living class). Status **Draft — explicitly non-binding**: it is vision, not architecture; no build order, no conduct rule, no schema force flows from it.
2. **Promotion is by ordinary decision only.** A piece of a concept foundation enters the Architecture State, the Schema, or the rule-set exclusively through the normal loop (conversation → decision → protocol) when its named trigger fires. The document's own refresh is the ordinary revise loop.
3. **Session captures remain frozen traces** (Conversations/, dated, C-062 class) — they feed the foundation; the foundation cites them; neither replaces the other.
4. **A public blueprint is a projection.** If a whitepaper ships, it is a **stamped C-035 compression of the concept foundation** — one source, never two diverging visions; the publish itself is a ship-boundary decision recorded when real.

**Precedent and fit:** the Knowledge Path Foundation is the class's ancestor (concept before architecture, KG before the store existed); C-062/C-085 hold the pre-canon boundary below it; the Architecture State holds the accepted-architecture boundary above it. The class fills the only empty rung.
