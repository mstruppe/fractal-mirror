## 2. The decisions (C-091, C-092)

**C-091 — reference copies govern nothing (Settings rule 9).** A session in a release copy — detached HEAD, release tag, any working copy that is not the instance's own governing repository — is a reference surface: it reads, explains, and midwifes GENESIS births; it never closes, never edits canon, never writes the store, never pushes (C-064 does not travel into a copy). *Why constitutional rather than mechanical:* the hazard (fieldnotes entry 15 — the clone session offered to run the mother's close, and the owner's key can reach the real remote) is a *jurisdiction* error, and jurisdiction lives in the conduct source; a marker file would be one more artifact that could go stale, while the adapter already ships in every clone by construction. The rule is kernel — every instance's distribution copies inherit it.

**C-092 — adopt before invent (Settings rule 10).** Before building any new working tool or projection, a session checks the shelf of specified components (GENESIS §5; in the mother, the Rule Overview and Architecture State) and offers the existing one first. *Why the duty sits on the AI surface:* §5 is read once at birth, before any need exists; the felt absence fires mid-work, when nobody rereads genesis documents (entry 22 — the Agenda Board reinvented within a day, its §5 row naming that very trigger). Tiering without discoverability at the moment of need silently converts saved carrying cost into reinvention cost — so the discovery mechanism is part of the minimality strategy, not an amenity. First adopted fix on OQ-28's discoverability half; the weight verdict itself still belongs to arc 2.

The C-071 ordering held: Settings moved first (→ v0.8, rules 9–10), then `CLAUDE.md` → v0.8 (content: the two rules + the scripted first-contact reflex) and `AGENTS.md` → v0.8 (stamp-only, by scope: a drone never governs and executes briefs rather than inventing tools — the reasoning recorded in its revision history, C-077 discipline).
