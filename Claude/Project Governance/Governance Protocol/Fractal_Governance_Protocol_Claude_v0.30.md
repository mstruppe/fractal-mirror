## 2. Evidence of record (what the corpus actually supports)

**a) The self-hosting claim is true, and it is the asset.** Four prior Code sessions, 77 decisions, three canonical Scans, a drill-proven rehydrate, and a close ritual that catches its own drift mechanically. Scan #3's shape — **8 findings, 0 High, every one in a declared checker blind spot** — is the substantive evidence: the drift rate is now below the system's own detection floor. Nothing in the vision requires re-proving this.

**b) The kernel has never been separated from its biography.** FRACTAL has governed exactly one project: itself. The repository interleaves **portable substrate** (format, tools, ritual, spine shape, adapters, governance roots) with **this project's history** (the Register's project decisions, the protocol series, Local Contexts, Return Packages, Scans, the store's own contents, the `KG`/`AST` roots). Nothing on disk is wrong; the seam has simply never been named. It is now — Architecture State **§6**, this session's structural deliverable.

**c) The seam runs through the Decision Register.** Roughly **40 of C-001–C-077 are kernel constitution** — substrate decisions a new instance inherits as given rather than re-deciding (C-018–C-020, C-022–C-027, C-037, C-040–C-046, C-049–C-050, C-055, C-059–C-061, C-065, C-073–C-077). The remainder is biography. An instance therefore starts its numbering **above an inherited line**, not from C-001. The exact partition is arc 1's first deliverable; the count is an estimate awaiting it, and is recorded as such.

**d) `BOOTSTRAP.md` points backward; nothing points forward.** BOOTSTRAP answers *rebuild this instance from its own history* — drill-proven since 2026-08-13 (C-038). No document answers *birth a new instance with an inherited constitution and an empty history*. **Genesis is the missing document**, and its absence is precisely why FRACTAL cannot yet be instantiated. The three landed OQ-16 slices (`/fractal`, `close.py`, `/close`) turn out to be pieces of a frame that was never built — arc 1 supplies the frame they belong to.

**e) The tracker is the right first instance because it is not a documentation project.** It stresses the doctrine where the doctrine has never been stressed: **live data** (a price feed would cross the C-055 tripwire in an afternoon — but that is the wrong reading: market data is *derived, disposable, refetchable*, squarely the C-019 cache tier, while what the canonical log records is theses, positions and rebalance reasoning); **code as a governed artifact** (the corpus governs prose plus four small tools — the tracker is an application, and whether source files take DOC identities is unanswered); and **secrets** (nothing canonical has ever held a credential, and this must be decided *before* the first key exists). The prediction of record: the two-tier C-018/C-019 doctrine comes out of arc 2 **stronger, not strained** — this is the sharpest test it has faced.

**f) Federation — the layered verdict, and one corrected expectation.** The examination expected a naive merge of two stores to corrupt silently; it does not. `verify.py` raises a hard **`CODE COLLISION`** error (its collision-verdict pass), downgrading to a warning only when the losing subject has been re-minted off the contested code. **The substrate already fails safe** — which materially improves the federation story and is recorded here because the opposite was assumed at the outset.

- **Identity merges free.** Ids are `TYPE-ULID` with an 80-bit random tail; independently built stores never collide, and merging logs is concatenate-and-sort — exactly what the tools' `load_log` already does. This was never designed for federation; it falls out of the ULID and append-only choices. It is real luck and real architecture.
- **Codes collide by design.** Codes form one global namespace across all facets (C-044) under first-mint-wins (C-049), so **every** instance anywhere mints its own `GOV`, `CTX`, `GBL`, `FACET`, `AGENT.HUMAN.*`. The existing cure (re-mint the loser + redirect alias) is built for accidental collisions between two writers in one project; applied to a foreign namespace it would mean rewriting the stranger's entire code space, destroying the provenance that made the merge worth doing. **The cure is therefore an origin layer — foreign codes never enter the local namespace — not a relaxed guard.**
- **Meaning stays human, by doctrine and not by difficulty.** Fully automatic semantic merge is not *hard*, it is *wrong*: two people's ontologies are not machine-reconcilable, and pretending otherwise would violate C-018's "human retains interpretation." The right shape — lossless ingestion, machine-checked structural merge, human-mediated bridging via minted `same-as` events — is better than seamless merging and should be presented as a feature, not a limitation.

**g) The honest counterweight — the weight dial (OQ-28).** FRACTAL earns its overhead where the valuable artifact is *reasoning*. Where a project's value is throughput, the ritual will exceed the return. If instantiating FRACTAL means carrying ~78 decisions, a 30-entry protocol series and a full Scan apparatus, **nobody will do it — including Max, on project three.** Recursive simplicity says the kernel must be the smallest thing that still yields memory across sessions, with everything above it opt-in. This is recorded as a live risk to the program, not as an objection to it.

## 3. Decisions of record

- **C-078 — the instantiation program (Working Decision).** Adopted in order: **arc 1 kernel extraction** (cut the seam, write genesis + its tool, partition the Register) → **arc 2 the portfolio live tracker** as first foreign instance → **arc 3 federation**, deferred until two instances exist. **The decision adopts a direction and an order, never a design** — each arc opens with its own work and its own calls. **Ordering rationale:** arc 1 unblocks both successors; arc 3 waits because specifying a merge protocol against a *hypothetical* second store is specification ahead of need — the discipline OQ-4 has held to since 2026-08-13 — and arc 2 produces the real one. **Roadmap H is absorbed, not displaced:** the shipping tier *is* arc 1, and the index server's C-068 trigger ("inverted-view reads becoming routine") genuinely fires around arc 3, since a second instance is what makes inverted-view reads routine; WS (OQ-23) is untouched.
- **Max's vision enters canon as an ordinary decision on its own merits — the OQ-22 pattern.** Vision material informs; it does not govern until a decision carries it. C-078 is that decision, and it cites the corpus, not the ambition.
- **OQ-28–OQ-31 opened:** the weight dial · code as a governed artifact · secrets doctrine · federation namespace + trust. Each carries the arc that resolves it, so none is a floating intention.
- **OQ-4 annotated, and pointed at its own resolution.** A **second candidate** is now named — *FRACTAL first governing a project that is not itself*. Max's call: **not yet** — flag it, let it fire at arc 2 rather than on the intent to try. - **C-079 — the kernel is tiered (Working Decision; arc 1's first partition rule).** Raised by Max at the moment of starting arc 1: *"KG search/index is also still open. Something we may want to fix before the kernel extraction?"* The answer of record is **no — but decide its tier membership first**, because tiering changes what the partition looks like and costs one decision instead of an arc. **FRACTAL ships a specification for reads, not an implementation:** the Navigation Contract is kernel; **tier 0** (the grep ritual) requires nothing beyond the repo and is where every new instance starts; **tier 1** (the `resolve`/`enter`/`trace`/`history` index server) is **kernel-optional**, built on the C-068 trigger, which has not fired. Grounds: an index is a C-019 derived, disposable cache and cannot be load-bearing for a seam running through canonical text; a newborn instance has near-zero nodes, where grep is *correct* rather than merely adequate; shipping an MCP server in the minimum viable kernel would build OQ-28's bloat in at birth; and constructing it mid-partition would make the partition a moving target. **Recorded honestly:** arc 1 completes the **skill** packaging tier but *not* the **plugin** tier, since `BOOTSTRAP.md` §2.2 defines the plugin as *skill + MCP index server + entry commands* — Max's own observation that arc 1 and the H shipping tier are "basically the same" is confirmed with that one precision. **Second-order value:** tiering is the mechanism OQ-28 will use — *minimum viable* becomes a question of tier membership rather than of cutting features.
- **Two inherited questions land *inside* arc 1, recorded before it starts** (so neither closes by accident): **OQ-13**'s rename re-fires here, its named trigger being the OQ-16 packaging pass, which arc 1 *is*; and **S3-2.2** sits on two **kernel** documents (Schema v0.6, Navigation Contract v0.1) — it closes for free if the arc reissues either, and must otherwise be left open deliberately rather than shipped as a known-open finding on two of the kernel's own specs.
- **OQ-16 annotated** with a forcing event (arc 1 must decide the packaging unit, so adapter generation cannot stay undecided) and **OQ-27 annotated** (federation is its at-scale case: ingesting a stranger's instance means trusting a writer never inside Max's custody, which fires the armed per-writer-key rung; OQ-31 takes the mechanics, OQ-27 keeps the trust half).

## 4c. OQ-13 closed permanently (C-080) — the fifth disposition, and the last

Max, on being offered the genesis tool as the next step: *"OQ-13 is getting annoying to always pop-up, it feels like a duct tape fix. Can we eliminate the issue for once?"* Both halves correct. OQ-13 had been swept, deferred, re-swept, and resolved-as-keep across four dispositions since 2026-08-12; **a question that keeps returning is itself the defect**, and the cure is to fire its trigger and remove its subject rather than re-defer it with a better note.

**The trigger had genuinely fired.** OQ-13's same-day resolution named *the OQ-16 packaging pass* as a re-fire boundary. Arc 1 **is** that pass — the boundary simply arrived hours rather than months later. The disposition was correct as written and worked as designed; this is its execution, not its reversal.

**The argument arc 1 supplied, which did not exist that morning:** `GENESIS.md` instructs a stranger to copy the kernel by filename. An unrenamed file would therefore have shipped a C-012 violation into **every future instance, permanently** — a filename claiming `v0.1` over a document reading v0.3, v0.21, or v0.6. The kernel is the public-facing boundary; nothing further needed to be waited for.

**Two discoveries made it cheaper than the ledger implied.** (a) **The store had already settled it** — all three DOC nodes carried *versionless* aliases from the moment they were minted, so only the `Repo-relative path:` field lagged. The rename brings the filesystem into agreement with the knowledge layer, not the reverse. (b) **The frozen-citation problem, which is why this kept being deferred, did not exist:** `check_versions.py` already skips path checks inside frozen sources by design, on the principle that *a frozen artifact's paths are historical fact*. The RENAMED-map mechanism proposed for this work was therefore **unnecessary and not built** — the design had anticipated the case. Eleven frozen artifacts keep the old paths, correctly. The live surface was **13 files**, not the "~36 references" the ledger cited.

**The class, not just the instances.** Renaming three files removes today's violations; it does not prevent tomorrow's. `check_versions.py` now **errors** when any document in its LIVING registry carries a `_v<digits>` token in its filename — unit-tested against all three retired names, all ten current living documents, and two synthetic future violations. This is what makes the closure permanent: the rule moves from prose and discipline into the machine, and OQ-13 is left with **no remaining trigger**. C-012's grandfathering clause and the Context Index's naming paragraph are retired outright rather than annotated.

**Adapter note (C-077 discipline).** `CLAUDE.md` → v0.4 and `AGENTS.md` → v0.5 are **path currency, not re-projection**: the files they point at were renamed; their behavioural content and their Settings v0.6 stamps are untouched. A rename is not a doctrine change, and the distinction is recorded in the checklist row so the C-077 walk keeps seeing it.

- **`genesis.py` → drone** (not yet built). Bounded scope, spec already complete (`GENESIS.md` §1–§3 + Architecture State §6), and a **machine** acceptance gate. This is the `close.py` shape exactly — drone-built on a bounded brief, independently acceptance-tested, canonized as C-073.
- **The skill packaging unit → not drone-able, and not a judgment call.** C-066 bars drones from governance acts; the planned `SKILL.md` carrying the conversation rules *is* a C-065-class canonical adapter, and landing it forces **OQ-16** to a decision that belongs to Max. A drone can touch neither half.

**The gate was set deliberately harder than the repo's usual one:** both checkers must pass **inside a birthed scratch instance**, not merely in FRACTAL. A tool that leaves this repo green while producing a subtly broken instance would pass a naive gate and fail the only test that matters.

**Isolation:** the flight runs in a **separate git worktree** on `drone/genesis-tool`, so it cannot collide with this close on `main`. Sandbox is `workspace-write` — writes confined to the worktree; the brief was amended accordingly to run its acceptance test inside the workspace rather than `/tmp`.

**Why arc 1 was not finished in this session (recorded reason, per C-059).** The planned `genesis.py`'s real acceptance test is *birth an instance and close a session in it* — that test **is** the deliverable's value. A genesis tool that looks correct but produces a subtly broken instance is worse than no tool, because it would ship broken instances silently and the first to discover it would be a stranger following `GENESIS.md` §6. That test deserves to be a session's main event. Additionally, **OQ-16 wants the tool to exist first**: the skill should package the *automated* genesis path, so building it before the tool would mean building it twice.

**One process datum worth keeping.** The first launch **silently failed** — an invalid CLI flag meant the drone never started — and this was caught only because the flight was *verified* rather than assumed. The C-066 gate assumes a drone that ran; nothing in the doctrine yet checks that it did. Recorded as an observation, not a decision; if it recurs, it earns a rule.
