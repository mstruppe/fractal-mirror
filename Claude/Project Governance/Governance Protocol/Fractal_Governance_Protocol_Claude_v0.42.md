## 1. The decision (C-097)

**C-097 — the client library (the entry-16/17/32/36 bundle resolved).** The kernel carries **one catalog of vendor surfaces** — `Fractal_Client_Library.md` (Governance Documents) — one entry per client an instance can be worked from, each providing the **discovery convention** (which file the client auto-reads), the **session-capable adapter template**, and the **client mechanics** a user needs. Set up once; instantiated per instance. Four boundaries, all doctrinal:

1. **Never a second conduct source:** every instantiated adapter remains a C-035 projection of its instance's own Settings (C-065), stamped and machine-checked — the library supplies skeleton and client knowledge, never rules.
2. **No runtime API** — Max's stay-up-to-date instinct honored without the dependency: an instance calls nothing upstream (the constitution model, fieldnotes entry 28). The library stays current through the **C-094 loop** (client changes under real use → `/fieldnote` → ingestion → revision); a refresh may consult vendor docs as a session act.
3. **Field-forge, then harvest:** entries are generalized from adapters ratified in real use, never authored from theory. First exercise built in: the Codex/ChatGPT entry is **harvest-pending** on KNet's `AGENTS.md` ratification.
4. **The universal layer is the word, not the menu:** the session vocabulary (*orient · close · fieldnote*) works as plain words on any surface whose adapter names it; menus are per-client dressing (entry 36's universality ceiling, stated honestly).

**Landed at issue:** the library v0.1 with the Claude Code reference entry (proven) and the Codex/ChatGPT entry (mechanics field-observed, template harvest-pending). **Armed, not built:** the `genesis.py` client parameter (fires when a birth onto a second client is demanded, C-021); the GENESIS §5 shelf row (lands at GENESIS's next batched reissue — recorded in the library so it is not forgotten). **Kernel rule;** an instance's client roster is biography.
