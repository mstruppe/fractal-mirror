## 1 · The doctrine (why pairs)

The AI works from a **governance spine**; the human should never have to read it to know where things stand. So every human-facing window is the **derived half of a pair** whose original is a governance document: one substrate, two reader-matched faces (C-122 — the mirror doctrine). Five laws govern every pair:

1. **The original governs, the user half informs.** The user document is a derived projection (C-035 class) — when the two disagree, the original is right and the projection is stale; the stamp naming the original's version and date *is* the divergence signal.
2. **One home, pointers elsewhere.** The content lives in the original; every other projection — the board included — links it instead of carrying it (the diet discipline, C-095 class).
3. **The sorting rule** (C-122): a change to the *path* lands on the stable pole, *work* lands on the dynamic pole, anything *surfaced mid-task* lands in the buffer.
4. **Structure holds the reasoning's standard (C-125 — the takeover gate).** Governed structure here *takes over interpretation the AI agent's reasoning previously carried ungoverned* — and it inherits that carrier's standard whole: **nothing the richer carrier held may be dropped in the handover.** The mechanism is §3 step 4's gate; the responsibility is the owner's sentence of record — *"the governance structure needs to hold this standard and constitutionalise it."* Structure carries the facts and the law; interpretation stays a live act each session — the guarantee is lossless handover, traceable citations, and a divergence signal wherever structure and reality part.
5. **The seed-tree law (C-131 — v0.3).** The kernel's half of every kernel pair is a **built-but-empty seed**: structure plus operating instructions, zero content. Filled content is *always* instance growth — instance-class by definition, even in kernel document series. *Empty form = kernel, growth = instance* is the pair series' partition test.

## 2 · The kernel tier — three pairs, fixed (every instance has these)

| Governance original | User half | The window it gives the human |
|---|---|---|
| **Global Context** (stable pole — vision + realisation) | **Roadmap** | the path: the big moves in order, phase grain |
| **Local Context** (dynamic pole — the state of work) | **Agenda Board** (Fractal_Agenda_Board_Format — ships at birth) | the state: where work stands, session grain |
| **Fieldnote buffer** (the shared write-surface — governance-side, RAM per C-121) | **Fieldnote Handout** | the manual: how to operate the one organ the human writes into |

The three **governance originals exist from birth** (Global, Local, and the buffer are all born at genesis), so the pair shape is kernel, not optional. **Since v0.3, the user halves exist from birth too** — see the seed law below. A newborn learning the system learns exactly this table — these are *the user docs already done*.

**Where the halves live (C-126 — the location law; amended by C-131, v0.3):** all user halves live together in **one dedicated folder at the repo root — `User Documents/`** — the human's own place in the folder system, openable directly without asking the AI and without descending into governance territory. **Governance originals stay in their natural homes** — the pair split is visible in the folder system itself. **The folder is born at genesis, already built but empty of content (C-131 — superseding v0.2's born-on-first-use clause):** it carries the instantiated kernel seeds from the first day, each filled only with instructions for operating it. The user halves cross-link relatively, so the folder moves as one piece.

**The seed law (C-131 — v0.3).** The kernel ships the trio's halves as **v0.0 seed editions** in `Templates/` at the repo root (`Fractal_Agenda_Board_Seed_v0.0.html` · `Fractal_Roadmap_Seed_v0.0.html` · `Fractal_Fieldnote_Handout_Seed_v0.0.html` · plus the buffer's own shape, `Fractal_Fieldnote_Buffer_Seed_v0.0.md`), and `genesis.py` instantiates them at birth — placeholders filled, nothing else. Two disciplines make the seeds an upgrade path rather than a burden:

- **Discipline A — frozen editions + grown-from stamps.** Seed editions are frozen, versioned artifacts (C-040 class); a structural change is a new edition. Every grown document carries a **"Grown from:"** stamp naming its seed edition. Migration logic: a file still byte-identical to its seed edition is provably ungrown ⇒ mechanical auto-replace; a grown file enters the judgment path guided by the diff between the two seed editions (Kernel Migration Procedure class).
- **Discipline B — the bounded set.** Kernel seeds exist for the kernel trio only; extensions never get kernel seeds (they are instance-tier by §3). Every seed is a standing migration obligation for all future kernels — three pairs is cheap, an open-ended set is a tax. The **coupling row**: a Format reissue that moves a seed's governing structure (e.g. the Agenda Board Format) triggers a seed-edition check, carried by the C-059 walk's pair-series row (the Schema → Template coupling precedent).

## 3 · The extension process (the simple standardized way to add a pair)

Not every window is universal — an instance adds a pair **on felt need, never by anticipation** (the C-079 tier rule). Five steps, one sitting:

1. **Name the pair.** One governance original — living document, stable filename, in its natural home — and one user half in the instance's **`User Documents/`** folder (§2's location law), beside its other windows.
2. **Declare the roles in both banners.** The original: what it collects, and its **content class** — durable, or **RAM** (temporary by construction; if RAM, state the dissolution rule: where the content freezes when spent, per the C-121 pattern). The user half: *derived projection of `<original>` — when the two disagree, the original is right*, stamped with the original's version/date.
3. **Wire the glance-path.** The user half joins the **user-document bar** on every user document (the Board Format's bar grammar — one pill, `name — the <role>`, extension pills after the kernel four; absent entries are deleted, so the bar always tells the truth).
4. **Point, never duplicate — and walk the takeover gate (C-125).** Every projection that previously carried the content now links the original and says only what state it is in (the board's grammar: *`<name>` — open* → link). **Before the pointer replaces the carried content:** trace **every fact** of the replaced carrier — prose, agent-reasoned nuance, parenthetical constraints included — to its one new home (the Diet Procedure's fact-presence gate, generalized to every takeover); then the behaviour test — the slimmed surface still serves its reader end-to-end. A fact with no home either moves into the original **before** the replacement lands, or the replacement does not land. The gate is not diligence, it is law: the first walk of it caught a real loss in the very session that wrote this procedure.
5. **Record the adoption.** One decision row (`P-…` / `C-…`) names the pair, its content class, and its retirement rule — a pair born on felt need retires the same way: deleted whole, the bar entries with it, the decision row the memory.

## 5 · Adoption and the checker half

- **An existing instance** adopts this procedure by its own recorded decision (Registry rule 5) and applies §3 whenever a window is wanted. **Adopting v0.3 includes the seeds:** copy `Templates/` from the pinned kernel release, instantiate any kernel half the instance lacks, and add the Grown-from stamp to any half it already grew (the stamp declares which seed edition the document's structure conforms to — retroactively true by construction).
- **A newborn** is born with the folder and the instantiated seeds (C-131): the §2 table tells it what it was born with; §3 tells it how to grow more — nothing to install, everything to know.
- **Checker half:** prose-first (Registry rule 2). Build trigger: the bar's mechanical verification, the seed hash-match check at a migration, or a conformance dispute. `check_versions.py` walks `User Documents/` and `Templates/` since S6-2.2 — the claim layer is already machine-guarded.
