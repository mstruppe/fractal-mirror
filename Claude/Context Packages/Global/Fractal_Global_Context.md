## 1. Vision

FRACTAL is a unified knowledge and research environment — an operating system for structured knowledge. It exists to eliminate the fragmentation of real investigation, where every switch between web, AI, literature, data, notebooks, code, and prose forces context to be rebuilt. It folds the whole lifecycle — gather, organise, analyse, model, connect, communicate — into one continuous workflow, and preserves the *entire reasoning process*, not just results. It is domain-independent, treats AI as a transparent collaborator while the human retains interpretation and decisions, and views knowledge as an evolving, interconnected structure rather than isolated documents.

Its guiding philosophy is **recursive simplicity / minimal necessary complexity**: complex understanding emerges from repeatedly applying a small set of simple, composable rules; begin from the smallest abstraction and add only what an observed problem requires. The same pattern repeats at every scale — project → domain → component → conversation → task.

## 3. How the context system is shaped

The context spine has two poles: this **Global Context** (stable — vision + current realisation) and a **Local Context** (dynamic — a specific aspect of the current realisation, following the vision). Every Local Context opens by naming which aspect of the current realisation it addresses, which keeps it locked to the vision through this document. Domain, Task, and Return packages are the scopes and mechanics by which a Local Context is worked and handed between conversations.

**The same shape projects once more, for the human (C-122 — the mirror doctrine; standardized as the user-document pair series, C-124):** every human window is the **derived half of a pair** whose original is a governance document — one substrate, two reader-matched faces. **Three pairs are kernel, fixed:** this document ↔ the **Roadmap** (vision + trajectory, phase grain) · the Local Context ↔ the **Agenda Board** (the state of work, session grain) · the **fieldnote buffer** (C-121 — governance-side, the one surface both writers share) ↔ the **Fieldnote Handout** (its manual). **Everything further is an instance extension**, added on felt need by the five-step standard (`Fractal_User_Document_Pair_Procedure`) — the mother's first: the **Update Plan** pair, the release lane's one home, the board slimmed to a status-plus-link. The sorting rule: a change to the *path* lands on the stable pole, *work* lands on the dynamic pole, *what surfaces mid-task* lands in the buffer — for both readers.
