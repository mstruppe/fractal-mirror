## §0 THE DISTILLATION

### Tagline

**Chats forget. Your project doesn't have to.**

### One-liner (GitHub description)

Project memory for AI-assisted work that outlives every chat: decisions, reasoning, and next steps as plain text in a git repo you own — read at the start of every session, written back at the end — so the work survives dead threads, new machines, and vendor swaps.

### Three sentences

FRACTAL gives an AI-assisted project a memory that outlives every chat: each session reads its context from plain-text files in a git repository you own and writes its decisions back before it ends, so the next session picks up where the last one stopped. It works with any AI agent that can read your files — the memory is a git repo, not a vendor feature; proven in the field when one project switched from Claude's CLI to the ChatGPT desktop app mid-stream. This is not a bigger context window — a session reads a short, current summary, not every word ever said — but the full record behind it (every decision, its reasoning, what comes next) is versioned, greppable, and machine-checked: two small dependency-free scripts refuse the handover if the record disagrees with itself. It already runs: this repository is the first instance, fourteen sessions of its own development on the record; a second project, started from a signed release, switched from Claude to ChatGPT mid-project without losing its thread; and rebuilding everything from a fresh clone has been drilled, not assumed.

### Homepage opening (~150 words)

Weeks of context in one chat thread, then the thread hits its limit and dies. The next session starts ignorant — you paste summaries, re-explain old decisions, watch the AI contradict things it settled last week.

FRACTAL moves the memory out of the chat entirely. No server to run, no database, and nothing phones home: the record — every decision, its reasoning, the next step — is plain text in a git repo you own. Sessions open by reading it and close by writing a handover back; two small scripts refuse the handover if the record disagrees with itself. The memory is files, not a vendor feature — one project switched from Claude to the ChatGPT app mid-stream without losing its thread. The founder's field note reads: "usually you're vendor bound to get memory within projects."

This repository is the first instance: fourteen sessions of its own development on the record; every release ships as a signed tag with an independent OpenTimestamps receipt; recovery from a fresh clone drilled, not assumed. Not infinite memory — owned, verifiable, vendor-independent memory.

## §1 THE ORIGIN

### The classical story, in the founder's own arc

FRACTAL's origin is the target reader's biography. The founder's own account of it (FN-0004, 2026-08-16, recorded as he read this capture's distillation): the seed was planted in ChatGPT with "the very classical story" — one very long conversation, context lost, workarounds attempted with AI-drafted summaries — out of which the idea of global and local context grew, which birthed FRACTAL. The founder hit the same wall FRACTAL's users hit, tried the same workarounds they try, and built the structural answer when the workarounds failed.

The record backs the shape of that story precisely. FRACTAL did not begin as a memory system. It began in ChatGPT as the "Fractal Research Ecosystem" — a modular research environment for two economics problems its builder was carrying [Fractal_Research_Ecosystem_Project_Protocol.docx §3.1–3.2]. The imagined product was a recursive 3D workspace: sparse node-spaces entered through wormhole-like transitions, a visible "cave thread" trail guaranteeing a path home, and an "empty house" requirement — the app must feel finished before its content is, so unfinished work can be reliably reopened [ibid. §4.1–4.5]. The declared value was persistence before intelligence — literally, the doctrine "Persistence before intelligence" [ibid. §4.2, §10]. The era's Genesis Protocol fixed an epistemic core that still governs today: reasoning explicit, inspectable, revisable, cumulative; decision records with confidence and revision triggers; "The software documents itself" [ibid. header 'Core principle' row, §10 doctrine list, §13].

Then the medium failed the work. The ChatGPT era planned a canonical Architecture State from a 17-part, 74-chapter Master Index and wrote only chapter one; no code was ever built. The chats themselves — finite, forgetful, unsearchable as a system of record — had become the constraint. The final ChatGPT-era document (2026-08-02) is the collision resolving: Max names the token bottleneck as "a big issue which I think requires immediate action" [proposed workflow .docx, opening [Max] paragraph], and the conversation designs the four-layer context system FRACTAL now runs on — Global/Domain/Task context packages plus the Return Package as "a state transfer object", "not a transcript" — along with the doctrine that a context package "must never silently become the source of truth" [ibid.]. The same document predicts its own future: the workflow "becomes [the Knowledge Graph's] first working prototype"; "the project could bootstrap its own architecture through its development process" [ibid. 'Speculative mode']. That prediction held: the research environment's first prototype turned out to be the process designing it. CLAUDE.md rules 1–5 today are the August-2 workflow, operational.

## §4 WHERE IT HEADS

### The five layers, with build-status precision

The stack is instance → portfolio → federation → society → economy. The precise status, per the record: **layer 1 (instance) is live and proven; layer 2 (portfolio) exists but is deferred to arc 2; layers 3–5 are vision with named triggers, non-binding by rule (C-086).** The vision tier lives in a canonical concept document that is Draft and explicitly non-binding: "vision, not architecture — nothing here binds a build."

Its thesis extends the founding problem one scale up: research fragmentation is a context tax between projects and people; the unit of exchange is the "decisive increment," extracted as a byproduct of the close the AI already performs — the answer to the failure mode its predecessors share (nanopublications, ORKG, Discourse Graphs: extraction labor with no worker and no wage). Verification is a two-layer gate (checkable standards, then skin-in-the-game registration and replication); governance collapses to selecting standards from a catalog; the economy mints currency on verified contribution to finally pay replication labor — with restraint pre-committed: genesis imports mint nothing, the coin stays non-cash as long as possible.

### Trigger-armed honesty

The honesty is structural, not rhetorical. The dragons are named in the canon — three held by design (issuance, collusion, securities exposure) and two contributed by the network's own first child (distributional inversion, and the ledger as strategic history), both under live research in the child's jurisdiction, unresolved in the mother's. The whole tier operates as armed triggers constraining near design cheaply — "and nothing — nothing — is built before its trigger fires." The missing pieces are individually named, never vague: the origin layer + import verb (OQ-31), discovery/profiles (OQ-32), the verification gate (Foundation §5), the first FRACTAL-owned serving process (OQ-30, its secrets doctrine pre-answered). The accepted risk is itself on the record, in the pre-canon ledger: triggers may fire later than the market moves — a deliberate bet on the constitution model.
