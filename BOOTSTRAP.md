**Protection checklist (C-057 — layered custody, evident-and-reversible):**

1. **Device:** macOS account password + **FileVault** on (lost/stolen-laptop layer).
2. **Account:** the private repo is exactly one GitHub identity — enable **2FA (passkey preferred)**; no collaborators unless deliberately invited. Access tokens, if ever created (e.g. cloud-session read access): fine-grained, single-repo, read-only, expiring.
3. **Authorship & signing:** the git author field *attributes, never authenticates* (C-037 scope) — and so does the committer field, which is **mechanical plumbing with no governance meaning** (C-074a). Commit signing is **live** (fired at the first drone write) and **custody-scoped** (C-074b): one SSH key = Max's custody environment; a signature attests *where* a commit was created, never *which writer* authored it. Verification is bound via **`.allowed_signers` at the repo root** — on any fresh clone, rebind it: `git config gpg.ssh.allowedSignersFile <absolute-path-to-repo>/.allowed_signers`. **Drill check (S3-1.1, machine-checkable — the drill verifies the claim, not just the mechanism):** `git log --format='%G?' | sort | uniq -c` must show every commit from `b043982` (the first drone write, 2026-08-14 — where signing went live) onward as `G`, all earlier commits as `N` (pre-signing history: unsigned by design, unsignable without rewriting, C-037), and **zero `B`/`E`/`U` anywhere** — with one recorded exception class (observed at flight 4, per v0.35): **a drone commit made in a full clone (C-082) arrives `N`**, because a clone does not inherit the repo-local signing config; its custody attestation is the **signed gated-merge commit** that lands it. Forward cure: the launch procedure configures signing in the clone (same custody key, same environment — C-074b conformant), so the exception stays rare and dated rather than growing. **Per-writer keys arm at the first writer outside Max's custody** (cloud drone, collaborator machine) — not before. **GitHub `main` branch protection** (block force-push/deletion) is a **dormant recommendation** — checked 2026-08-14: rulesets are not enforced on this private repository under the current personal plan; it activates at a GitHub Team/organization migration or a public flip (C-075 annotation). Harder split available on observed need: Claude proposes on branches, only Max merges `main`.
4. **Knowledge layer (already in force):** append-only event log, content hashes (C-040), `verify.py` at every store-touching commit (C-050), `check_versions.py` at every close (C-060), no history rewriting (C-037) — any alteration is **evident and reversible, never hidden**.
5. **Secrets (C-087):** **no canonical artifact ever holds a secret value** — not the store, the log, a governed document, or committed config. The *fact* of a credential (name, purpose, scope, holder, issued/rotated/revoked) is knowledge and is recorded; the **value** lives in the environment layer — a `.gitignore`d env file or the OS keychain (the ignore entries ship in the repo). Secrets are **deliberately non-durable**: excluded from the off-site copy by construction, so the "laptop in the ocean" test *loses* them and rebuild = **re-issue against the recorded facts** — credentials are re-issuable, knowledge is not. Machine guard: **`doctor.py`** (the sixth store tool, landed at flight 4 per v0.35 — known-format secret scan over tracked files, values redacted, plus the ignore-entry check; `--write` repairs the deterministic).

**Public sharing is decided (C-098, 2026-08-16 — sharing became real):** the public artifact is **the raw repository** (full signed history — the provenance story whole; the exposure inventory accepted with eyes open), **phased**: the friends-beta ships first from a private curated mirror (temporary, retired at the flip), the raw flip at Max's moment.
