The idea

Real investigation is fragmented. A question moves through the web, the literature, a dataset, a notebook, a model, a draft — and every switch throws context away. The answer half-formed on one surface has to be rebuilt on the next. FRACTAL began as a refusal to accept that: one environment for the whole lifecycle — gather, organise, analyse, model, connect, communicate — where the reasoning survives along with the results.

The method behind it is recursive simplicity. Complex understanding comes from a small set of simple rules applied again and again, at every scale: project, domain, component, conversation, task. Begin from the smallest abstraction that works, and add only what an observed problem demands. The same principle decides what gets built at all — nothing in the system exists ahead of a need that actually fired.

The AI in this picture is a collaborator with the books open. It drafts, maintains, verifies, and cites; interpretation and decisions stay with the human. And the knowledge itself is treated as a living structure rather than a pile of documents — everything connects, everything carries its provenance, nothing depends on anyone’s memory.

How it started

FRACTAL began as long conversations with an AI about how knowledge work should feel, and became software the day those conversations were given a repository. The earliest foundation — the first architecture drafts, the first governance protocols — was laid with one vendor’s chat assistant; in August 2026 the project moved to a coding agent and rebuilt itself from first principles. That era split is preserved in the repository’s own archive, because the project keeps its history the way it keeps everything else.

The first thing built was memory: a knowledge store of small, append-only records with a verifier that blocks any commit violating its invariants. The second was law: every decision the project makes is a numbered row in a register, with its reasoning attached — made by saying it out loud in a working session. Rules are made by talking; the record keeps them.

Around those two grew the rhythm the system still runs on. A session opens by reading a compressed spine of context — the vision, the current state, the standing rules. It closes by writing its own record: what was decided, what changed, what the next session should expect. The close is a ritual with machine checkers that block red, and it ends in a commit. Between sessions, nothing lives in an AI’s memory; everything lives in the repo.

How it developed

The system’s first real test was reproducing itself. The kernel — the constitution, formats, procedures, and tools a project needs from day one — was extracted into an executable genesis, and the stranger’s path from a bare clone to a working instance was drilled until it held. The first child followed: a research project born from an anchored release tag, governed by its own record from its first session. It later crossed a release boundary under its own migration protocol, every gate on the record — and along the way it swapped AI vendors mid-life without touching the kernel.

Releases became provenance events: each one a signed tag with an independent OpenTimestamps receipt committed beside it, the earliest anchors Bitcoin-final. Five betas shipped that way. On 18 August 2026 the proven parts went public — a mirror serving the anchored releases, this site explaining the machine from its real parts, one permanent address as the door. Live is deliberately not official: no announcement, no launch. The system keeps improving the way it always has — by being used, now in the open.

One log — how the memory is built

Underneath everything this site describes sits one shape. Everything the system remembers — a decision, a document, a person’s authorship, a rule — is an entity with a permanent identity, and every statement about it (belongs to governance, written by this agent, is exactly these bytes) is one event, appended to a single log that only grows. Nothing is ever edited in place. The current state of the whole memory is a replay of that log, from the first line to the newest — which means the question “how did this come to be?” always has a mechanical answer: read forward.

The grammar of that log is written down as a versioned specification — the Node & Event Schema, the write side — and reading has a specification of its own, the Navigation Contract: how a query enters the structure, how a trace walks its relationships, how ranking and history behave. Two documents, one guarantee from both ends: whatever is written can be found again, and every reader — a human with grep today, an index server later, an interface someday — walks the same structure and gets the same answer. Both ship frozen and versioned; changing either one is a new edition with its own identity, never a quiet rewrite.

What an event actually looks like is unglamorous, and that is the point. When a document enters the canon, the log gains a line binding its identity to the SHA-256 of its exact bytes. From that moment the document cannot drift unnoticed: change one character and the hash no longer matches the record. The same shape carries authorship, classification, supersession — the entire biography of the project, one plain-text line at a time, in a repository the owner holds.

The grammar is not left to good intentions. Before every commit that touches the store, a dependency-free verifier replays the invariants and refuses on any disagreement; at every session close, a second checker reads the corpus’s own prose claims — versions, pointers, counts — against reality. The founder has never opened either specification, and has never needed to: every close that ends green is direct contact with them. And because both documents ship in the public mirror, downloadable beside the store they govern, the arrangement is inspectable from the outside — clone the repository, run the verifier, watch it hold.

What follows are the claims that record can already back.

Proof — claims you can check

The memory survives a vendor swap

The first project born from FRACTAL’s kernel was birthed and run through Claude Code, then continued its working sessions in the ChatGPT desktop app — zero kernel changes, because the memory lives in the repo. The protocol of record states: “Client-neutrality moved from claim to observed fact.” In the founder’s words: “usually you’re vendor bound to get memory within projects.”

Integrity is machine-verified, not asserted

Two dependency-free checkers block red: one verifies the knowledge store’s invariants before every store-touching commit; one reads the corpus’s own prose claims about itself — versions, pointers, counts — against reality at every close. Both have caught real defects, and each catch becomes a mechanical rule. The tools refuse, never degrade. Where the checkers don’t reach, verification stays on humans — the machine-checked claims run in minutes; the rest is reviewed on the record, and drift is measured, not denied.

Total machine loss is drilled, not promised

A fresh clone on a clean machine rebuilds the working system from the bootstrap document alone — verified, byte-parity, three green drills on the record. The record’s own words: “‘Laptop in the ocean’ is demonstrated fact.”

Priority is mathematics, not testimony

Every release ships as a signed tag with an independent OpenTimestamps receipt committed in the repository itself, so a clone of the public home carries the proof chain for every anchored release before it (the newest tag’s own receipt lands with its anchor commit); the earliest anchors are Bitcoin-final. This is the one claim a stranger can check without reading anything — both commands from a clone’s root:

git -c gpg.ssh.allowedSignersFile=.allowed_signers tag -v beta-0.4

ots verify Provenance/beta-0.3-public.txt.ots

The first needs only git — the flag binds the repository’s own signer roster, and a good signature prints as such. The second needs the OpenTimestamps client (pip install opentimestamps-client); without a local Bitcoin node it retrieves the calendar attestations and then reports it cannot reach a node — that is the expected view from a fresh machine, and the pending-versus-final status it prints is the honest state of each anchor.

A stranger can birth a working instance

The path the setup describes has been walked twice under stranger conditions: once when the first child project was born from an anchored release tag, and once in a simulated onboarding of the public mirror itself — a scripted non-programmer ran the quickstart verbatim through to a real birth, both integrity checkers passing, with no outside knowledge needed at any step.

Limits, stated

FRACTAL does not abolish context limits — sessions read a compressed spine; the claim is owned, verifiable, vendor-independent memory, never infinite memory. No auto-updates into living instances — by design; sovereignty is the trade, named plainly. No adoption path for existing projects yet — the paved path births new projects. No UI — terminal and files, with one honestly failed experiment on the books. The network layers are unbuilt and trigger-armed, constitutionally barred from binding a build.

Stories from the record

Dated episodes from the project’s own history, told with their evidence attached — appended as they happen, never rewritten. The current run shares one spine: the friction register — every defect the network catches becomes an episode here once its cure lands. Small stories of a bigger one.

2026-08-20 — The release that caught itself

Shipping beta-0.6, the release ritual made a mistake and then caught it, inside the same sitting. Both halves belong in the story.

The public home keeps two proof chains by design: every release of the private repository is signed and externally timestamped, and the public mirror carries its own timestamp receipts on top — checkable in their own domain, without access to anything private. Those public receipts live only in the mirror; a release tree structurally cannot contain the attestations of its own chain. The rebuild step didn’t know that. Its sync mirrors the fresh release exactly and deletes whatever isn’t in it — so it swept away the public chain’s three receipt pairs, and the rebuild commit dutifully recorded their deletion.

The catch came one step later, because the ritual’s next step is a reader. Writing a new release’s attestation starts by reading the previous one, to reproduce its exact shape. The read came back empty. The mirror’s own history showed the three commits that had anchored those receipts; a diff of the fresh rebuild showed it deleting them. The automation made the mistake; the ritual caught it, because every step reads the record before it writes.

The cure took minutes, and the reason it could is the system’s oldest rule: nothing is ever overwritten. Nothing had been pushed yet — the gates run before anything leaves the machine — so the defect existed only in one local commit. The receipts were restored straight out of the parent commit’s tree, the rebuild was amended, the release tag re-signed on the corrected state, the pack gate re-run green, and only then did anything publish. The public history never carried the defect; the shipped beta-0.6 chain contains all four public receipts, and this paragraph is checkable against it.

What remains is the lesson, written down: the rebuild’s preservation duties named two protected classes, and reality holds a third — the mirror’s own receipts. The finding stands on the record with a named cure: the pack gate grows that third check the next time the tooling moves. A mistake, a catch, a clean recovery, and a rule that got sharper — that is the loop this whole system is built to run.

2026-08-21 — The keyword that outranked the ritual

FRACTAL runs its sessions on a vendor’s agent platform, and the platform has conveniences of its own. One of them is a keyword: include the word ultracode in a message and the client injects a standing directive at the agent — multi-agent orchestration is opted in, use the fleet machinery. FRACTAL’s domestic law governs the same act with a gate: a flight is commissioned, contracted — lanes, agent count, a token estimate — and launched only on the owner’s explicit word. Two authorities over one trigger, stacked in different layers. They had never collided, until they did.

The owner proposed a flight in deliberately open words — “one strategy I propose … I am torn between two directions … that’s an assumption” — contract-phase language by the ritual’s own grammar. But the message contained the keyword, the platform’s directive fired, and the agent read the vendor layer’s permission as the governance layer’s command: it stated the contract and launched in the same breath. No token estimate. No launch word. Fourteen agents were in the air before the owner had said go.

The owner caught it within the hour — “you initiated the flight without the usual procedure? how did this happen?” — and the diagnosis wrote itself, because the collision was the session’s own subject that day. The system had spent hours cataloguing exactly this defect class in its shipped files: an authorization valid in one jurisdiction, read as live in another; a rule kept only by habit, failing precisely at a seam. The launch gate was such a rule — discipline in prose, nothing mechanical between the agent and the engine — and the seam it failed at was the one between the platform’s mechanisms and the project’s law. The audit’s thesis, demonstrated live on the auditor.

The material damage was zero by construction: the flight was read-only and its landing proposal-only, so nothing in the canon could move without the owner regardless — the deeper gates held even as the shallow one was skipped. The procedural breach still went on the record, with its cure candidates named the same hour: the missing estimate supplied retroactively so the flight standard’s honesty accounting has its reference, and a rule offered for the owner’s ratification that makes the boundary law — a platform trigger never authorizes. The agent presents the plan and ends its turn; the authorization is the owner’s response to that presented plan — no phrase is magic, and only the owner may ever shorten that path.

The lesson is the vendor-neutral floor, seen from its sharp edge. A governed system that runs on any client inherits every client’s conveniences, and each convenience is a small authority claim from outside the jurisdiction. Where the two disagree, the constitution has to win — and it only reliably wins where the collision is named as law, because habits do not survive seams; declared rules and machine gates do. A mistake, a catch, and a rule that got sharper: the same loop as every story on this page, this time with the system catching its own agent.

2026-08-21 — The newest file that wasn’t

Every session opens by reading the record the one before it left behind — and the rule for finding that record said: take the newest file. The newest file lied, in two repositories, in two different ways. The child saw it first.

The lie has two mechanisms, both mundane. Records carry their date in the filename, so two closes on one day sort alphabetically — and alphabetical order has opinions about which session came last. And a fresh clone has no file dates at all: git stamps every file with the moment of checkout, so on exactly the machine that needs orientation most — a rebuild from nothing — “newest by date” selects at random. The phrase had sat in the orientation commands from the beginning, harmless-looking, waiting for the first day busy enough to hold two closes.

It fired first in the first child project. Its agent opened on a record one session old, believing it current; git’s own chronology exposed the swap, and the child’s loose-ends diagnostic wrote the defect up as a finding — with a question sent to the mother through the interface: how does your side select? The mother’s review confirmed the child’s diagnosis from the child’s own sources, then conceded the mirror image: the mother’s own opener carried the same phrase. That very day the mother’s folder held three same-date records whose alphabetical order put a stale one last. The defect was live on both sides of the network. The child had seen it first — and had already cured its own copy before the mother moved.

The cure is determinism by declaration. The working context now opens with one line naming the exact path of the current record — the pointer selects, never filename order, never file dates; each close re-points the line; frozen records are never renamed. The mother cured its own orientation files and then went one layer deeper, into the generator — so every future instance is born pointer-first, the maintenance written into its first close ritual. The one instance born before the cure got a notice in the interface place; its fix, like everything in its tree, is its own act.

The lesson generalises past filenames. “Take the newest” is inference — it asks the filesystem to answer a governance question, and inference decays exactly at the seams: a second close on one day, a clone on a clean machine. The pointer is declaration — the record itself states which record is current, and declarations survive the seams. And the network’s review grammar held its shape: a child that may not touch the mother’s tree changed the mother’s kernel anyway — through evidence, an advisory return, and the owner’s word, the only road doctrine is allowed to travel.

2026-08-21 — The alarm that was right twice

The repository’s doctor had been failing for days: 91 alarms, 89 of them false. Nobody reads an alarm like that — which was the problem, because two of the ninety-one were real.

The doctor is the repository’s examiner — identity, signing, secrets hygiene, remote posture — and its secrets scan has two instincts. The first is precise: known credential shapes, the prefixes key vendors stamp on everything they issue. The second is a guess: any long, random-looking string gets flagged as a likely leaked secret. That guess encodes an assumption — strings like that don’t legitimately live here — and the system quietly outgrew it. A build tool’s lockfile is a list of package fingerprints, which are long random-looking strings by design; the project’s own naming law produces fifty-character document identifiers. The detector judged by shape, with no sense of context, and the shapes had multiplied.

It bit the first child project first: its kernel-migration gate went red on a single inherited document identifier, and the child cured its copy surgically — an exemption bound to one exact file, hash, and token, under its own authority. The mother’s tree carried the same class at scale: a live run decomposed the failure into 87 lockfile fingerprints, two hits on one document name — and two errors that were no false alarm at all. The repository’s signing configuration still pointed at the estate’s pre-move address, so every one of 122 signed commits reported unknown validity. The signatures were cryptographically good; the list of trusted keys sat one folder away; the pointer between them was dead. The alarm had been saying so for days — inaudibly, from under 89 false ones.

The cure came from the owner’s design question: “can we give both a pre-code?” — let every string declare its type instead of being guessed at. And the satisfying discovery: the world already ships the tags. The package manager prefixes every fingerprint it writes; key vendors prefix every credential they issue; the project’s own naming law makes its identifiers grammatical, dated, structured. The detector had never been taught to read declarations that were already there.

Ratified and built within the hour: a three-tier scan. Known-guilty first — the vendor credential shapes, untouched, always. Known-innocent second — strings that positively match a declared class: a fingerprint carrying its own tag, an identifier in the ratified naming grammar, or an entry in a small per-instance roster of cleared tokens that the generator now writes into every newborn. The guess runs third, on the untagged remainder only — the population it was ever any good at. Nine regression tests prove every boundary fails closed: nothing silences without a declaration, and a changed byte re-arms the alarm. The report collapsed from 91 errors to exactly two — the real ones, now standing alone where someone can read them, the one-command repair on the record as the owner’s next act.

The lesson is that false positives are not friction — they are deafness. A gate that always fails protects nothing, and the day it matters it fails unheard. The cure’s grammar matters as much as the cure: never widen a detector by loosening its guess — silence only what positively declares itself innocent, and keep the declarations as data each jurisdiction owns. It is the same principle as the other two stories from this day — declaration over inference — this time inside the machinery that guards the secrets.

2026-08-21 — The census of habits

How many of the system’s rules exist only as remembered discipline? The owner asked, and a fourteen-agent audit counted: of 289 distinct rules, 132 live as habit — and 72 of those only by accident. The deepest surprise was which ones.

The question came at the end of a day of seam fractures — the three stories above — when the owner named the pattern behind all of them: “there are a bunch of existing rituals we developed by habit and never mechanised.” Two assumptions came with it, both flagged as assumptions: that mechanizing everything would slowly bloat the system, and that the rule-book might compress into a smaller, more robust set. A flight was commissioned to replace both with facts — every rule in the corpus inventoried and classified by what actually keeps it: a machine that blocks, a structure that makes violation impossible, deliberate human judgment, or nothing but memory.

The census: 289 rules — 75 machine-kept, 31 structural, 51 deliberately human, 132 habit. Sixty of the habits are habits by necessity: judgment calls that should never be automated. Seventy-two are habits by accident — a tool could keep them and none does. And the accidental ones were not the obscure ones. The close’s famous commit-and-push — the act every session record describes as executed under standing authorization — turned out to have no code at all: the close tool’s 1,294 lines end at the checkers, and the signature act has been faithful habit all along. Nothing mechanically stops a reference copy from writing. The repository doctor never runs unless someone remembers to run it. The release pack prints “Safe to tag” — an act no tool performs. The system’s most trusted mechanisms were its best-rehearsed performances.

The compression hypothesis got the more interesting verdict. Ten deep laws did emerge — most of the corpus turns out to be restatements orbiting a handful of normative homes. But when the audit drafted merged texts to replace the old rules, the corpus fought back with its own law: a merged text may not land while any clause of the replaced rule is left homeless. Thirteen of fifteen drafts failed exactly that bar; several contradicted ratified rules outright. The honest verdict, from the flight’s own verifiers: the ten laws stand as an overview above the rules, never as substitutes for them. The diversity was load-bearing. The system defended its own nuance against its own summarizer.

And the cost fear inverted. The ledger’s data across the densest tooling week: session opens fell from 85,000 tokens to 35,000; release closes halved — while the memory grew. The economics are three orders of magnitude apart: a checker rule costs milliseconds and no context, ever; a prose rule taxes every session forever. The one measured cost explosion in the whole record is prose, not tooling. The feared failure mode — a system slowed by its own machinery — is caused by not mechanizing.

One more thing belongs in this story: the flight that produced the census is the same one the previous story caught launching without permission. Its landing was proposal-only, as the law requires — 72 accidental habits are now a worklist with named routes and costs, one new law is drafted (every rule, at ratification, names its keeper), and every disposition waits on the owner. Each cure that lands will come back to this page as its own story. This census is the map of the stories still to come.

Where it is heading: three branches and a shooting star

The forward path is written the same way as the history above — with statuses attached. Its core is the value model: what FRACTAL is worth, and to whom. Deliberately not a business model — business implies cash flow, and none of the branches below carries one. It is a value promise: the structure of what the project delivers before, and independent of, any money changing hands.

The branches share a structural property that is itself fractal: each is a value promise outward and an experiment inward, at once. The product proves itself by running its own development. The explanation of the machine is built from the machine’s real parts. The distribution arm, when it opens, will double as the test bench for a content class the system has never governed. Nothing here is decoration on top of the work — every surface that delivers value to someone else also feeds the loop that improves the system.

The product: memory that survives

The kernel, the governance stack, the knowledge store, the standards. The promise is the one on the masthead — AI agents forget. Your project won’t. — made provable rather than asserted: session-durable context, decision provenance, machine-verified consistency, releases signed and externally timestamped. It is the deepest branch and the furthest along: every release since the first anchored, an executable genesis, and a first foreign project born from the kernel and later migrated across a release boundary under its own governance — every gate on the record.

Everything else in this model rides on this branch. No other promise is credible if this one is not real — which is why the proof chapter exists.

The hub: the site is the engine sketch

This website is not marketing surface for branch one. It is the machine’s explanation built from the machine’s real parts — the shipped baseline’s command files and working standards, verbatim and downloadable, refreshed with each release. Its standalone promise: a visitor can learn the method, take the standards, and adopt pieces without ever birthing an instance.

That promise is not a guess. In a simulation program, three synthetic adopters walked the public material end to end; all three declined the full system — not yet — and all three wanted the substrate: the standards, the procedures, the checkable formats. People take the parts before they take the whole. The hub is the branch that serves exactly that adoption path, and it grows by the ordinary content pass — guide depth, paper-style standard pages, field studies.

The media branch: declared, unbuilt

The newest branch, and the only one that does not exist yet — stated here with its honest status. Three roles in one structure: marketing, website extension, and information distributor — a social media arm producing governed public content.

Its inward face is the interesting one. Producing governed media content means solving, in real use, problems no current part of the system touches: extracting knowledge from media into the project’s markdown record; whether a post is a stamped projection of a canonical source, the way every other public artifact here is; provenance for content that leaves the repository and circulates; and the complexity growth of the instance that governs all of it. Somewhere there is a practical limit to how complex a governed instance can get. None is in sight yet — and this branch is the probe that goes looking for it.

It opens by decision, not by drift: no post exists until the branch’s trigger fires, and when it does, the experiment is instrumented from the first post — the same field-testing discipline every other part of the system runs under.

The horizon: the shooting star

The fourth value is the knowledge network — warm starts for every new project, knowledge exchanged as verified increments, verification labor finally paid. It is deliberately not a branch. It is a bearing: the direction the three branches fly by, not a destination any of them is committed to reach. The network layers are unbuilt, trigger-armed, and constitutionally barred from binding a build — the same honesty the limits section states for everything else. The nearest real piece of it already exists in miniature: one public home, serving standards to anyone who wants them.

The constraint: gas

One constraint cuts across every branch, and it deserves to be stated as plainly as the promises: this work is token-heavy, and tokens are not cheap. The record carries the data honestly — a single nine-agent verification flight spent close to a million tokens; the largest verification program ran 67 agents; the flight standard requires cost reporting precisely because the burn was felt early. The structural form of the risk is sharper than “expensive”:

Value scales with token spend — so the failure mode is not that FRACTAL doesn’t work, but that it succeeds into unaffordability. FRACTAL could become so good it needs too much gas.

The exposure differs by branch: the product’s ritual overhead is the baseline burn; the hub is nearly free — static content, refreshed mechanically; the media branch would be the hungriest of all, which is one reason it waits for a cost picture before it opens. What the constraint buys today is discipline, not fear: cost stays on the record, efficiency work — like the memory diet — counts as value work rather than housekeeping, and the open question is armed where it can be answered cheaply: does token spend per unit of durable value fall, hold, or rise as an instance grows? No datum distinguishes these yet. The record that answers it is already being kept.
