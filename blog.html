Proof — claims you can check

The memory survives a vendor swap

The first project born from FRACTAL’s kernel was birthed and run through Claude Code, then continued its working sessions in the ChatGPT desktop app — zero kernel changes, because the memory lives in the repo. The protocol of record states: “Client-neutrality moved from claim to observed fact.” In the founder’s words: “usually you’re vendor bound to get memory within projects.”

Integrity is machine-verified, not asserted

Two dependency-free checkers block red: one verifies the knowledge store’s invariants before every store-touching commit; one reads the corpus’s own prose claims about itself — versions, pointers, counts — against reality at every close. Both have caught real defects, and each catch becomes a mechanical rule. The tools refuse, never degrade. Where the checkers don’t reach, verification stays on humans — the machine-checked claims run in minutes; the rest is reviewed on the record, and drift is measured, not denied.

Total machine loss is drilled, not promised

A fresh clone on a clean machine rebuilds the working system from the bootstrap document alone — verified, byte-parity, three green drills on the record. The record’s own words: “‘Laptop in the ocean’ is demonstrated fact.”

Priority is mathematics, not testimony

Every release ships as a signed tag with an independent OpenTimestamps receipt committed in the repository itself, so any clone carries the full proof chain; the earliest anchors are Bitcoin-final. This is the one claim a stranger can check without reading anything:

git tag -v beta-0.4  ·  ots verify Provenance/beta-0.3-public.txt.ots

A stranger can birth a working instance

The path the setup describes has been walked twice under stranger conditions: once when the first child project was born from an anchored release tag, and once in a simulated onboarding of the public mirror itself — a scripted non-programmer ran the quickstart verbatim through to a real birth, both integrity checkers passing, with no outside knowledge needed at any step.

Limits, stated

FRACTAL does not abolish context limits — sessions read a compressed spine; the claim is owned, verifiable, vendor-independent memory, never infinite memory. No auto-updates into living instances — by design; sovereignty is the trade, named plainly. No adoption path for existing projects yet — the paved path births new projects. No UI — terminal and files, with one honestly failed experiment on the books. The network layers are unbuilt and trigger-armed, constitutionally barred from binding a build.

Experimental designs

The claims worth making are the ones that can fail: whether structured context keeps agents right (a context-fidelity experiment with blinded scoring is running in the first child project now), whether it keeps them cheap (the tokens-on-new-context claim, designed to be measured against a bare-conversation baseline), and which engine at which capacity suffices for which use intensity.

Designs are published here when they freeze; results follow when they exist — including the ones that come back negative.
